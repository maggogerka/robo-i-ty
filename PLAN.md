# План первого инкремента «Робо&Ты»

Дата фиксации: 20.09.2026. Дедлайн проекта: 29.09.2026.

## Выбранный приоритет

Первым реализуется сквозной аналитический контур P0:

`исходные файлы → нормализованные данные → проект объекта → объяснимый подбор → экономика текущей работы / покупки / RaaS → русский интерфейс`.

Этот контур важнее 2D-визуализации и расширенного экспорта: без проверяемых входных данных, ограничений и формул визуализация не подтверждает инвестиционное решение.

## Что входит в этот инкремент

1. Зафиксировать реестр и ограничения шести входных источников из `input/`.
2. Создать воспроизводимые импортёры XLSX и CSV:
   - метаданные форм для склада, аэропорта и медучреждения;
   - 223 строки ценового каталога;
   - разделение продукта, кейса и источника.
3. Реализовать backend на FastAPI/SQLModel:
   - JWT-вход demo-пользователя и администратора;
   - роли и проверку владельца проекта;
   - проекты и параметры, создаваемые из метаданных;
   - каталог с поиском и фильтрами;
   - детерминированный объяснимый подбор;
   - чистый модуль экономики для трёх сценариев;
   - OpenAPI и healthcheck.
4. Реализовать frontend на React/TypeScript:
   - русскую главную и вход;
   - открытие демопроекта склада одним действием;
   - редактирование валидируемых параметров;
   - результаты подбора с вкладом факторов и ограничениями;
   - сравнение экономики базы, покупки и RaaS;
   - каталог с поиском.
5. Добавить Docker Compose, миграцию/инициализацию, seed и документацию запуска.
6. Покрыть тестами формулы экономики, ограничения и стабильность ранжирования, авторизацию и изоляцию проектов, основные API.

## Явно отложено на следующие инкременты

- полноценный React Konva-редактор и детерминированная 2D-симуляция;
- PDF/CSV-отчёт и пример выгрузки;
- импорт пользовательских Excel/CSV с экраном сопоставления колонок;
- полноценный CRUD администратора;
- расширенная чувствительность и графики;
- распознавание планов.

Интерфейс честно помечает эти функции как следующие этапы; API и модель данных проектируются так, чтобы добавить их без замены расчётного ядра.

## Критерии готовности инкремента

- приложение поднимается одной Docker-командой;
- demo-вход и демопроект не требуют ручного заполнения;
- формы трёх объектов строятся из импортированных метаданных;
- склад выдаёт не менее трёх объяснимых кандидатов при наличии совместимых данных;
- экономика не показывает срок окупаемости при неположительном эффекте;
- одинаковый ввод даёт одинаковый порядок рекомендаций;
- backend-тесты, frontend lint/typecheck/tests и production build проходят;
- исходный PDF на 85 МБ и остальные материалы из `input/` не попадают в git.
