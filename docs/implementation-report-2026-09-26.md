# Отчёт о разработке от 26.09.2026

Этот файл можно передать в другой чат как актуальный технический контекст проекта.

## Итог

В feature-ветке `feat/plan-recognition-mvp` реализован приоритетный P0-контур работы с планом объекта: безопасная загрузка, черновое распознавание через сменный provider, ручная проверка в 2D-редакторе, версионирование, план-зависимый подбор и детерминированная маршрутизация A*. Основная ветка не изменялась и не отправлялась.

## Реализовано

### Файлы и ревизии плана

- Форматы: PDF, PNG, JPEG, WebP, SVG.
- Лимит: 16 МиБ (`assumed`, политика MVP).
- MIME определяется по сигнатуре; расширению и заявленному Content-Type не доверяем.
- SVG с DTD/entity/script/event-handler/external URL/data URL блокируется.
- Файл хранится вне БД; в БД находятся SHA-256, размер, MIME, безопасное имя, относительный путь, владелец и время.
- Content endpoint проверяет владельца и возвращает `no-store`, `nosniff`, sandbox CSP.
- Каждое распознавание и сохранение создаёт `PlanRevision`.

### Распознавание и редактор

- Введён интерфейс `PlanRecognitionProvider`.
- `demo` всегда доступен, возвращает редактируемый шаблон и явно сообщает, что это не нейросеть.
- `yytsi_floorplan` — опциональный локальный provider для SVG; разрешены только `http://127.0.0.1`, `localhost`, `::1`, redirect запрещён.
- Редактор поддерживает фон, zoom/pan, выбор, drag, resize, создание/удаление, undo/redo, свойства, confidence, low-confidence подсветку, ручную калибровку и историю версий.
- Подтверждение требует масштаба для загруженного плана и контрольных точек забора/доставки.

### Маршрут и подбор

- Симуляция `2026.09.2` использует воспроизводимый 8-связный A*.
- Препятствия раздуваются на `robot_radius_m + safety_margin_m`; значения и единицы сохраняются как `assumed`.
- Сетка имеет ограничение числа узлов, чтобы большой план не создавал неограниченную нагрузку.
- Отсутствующий путь возвращает 422 и не заменяется прямой линией.
- Подбор `2026.09.2`: функциональность 25%, проходимость плана 25%, производительность 20%, экономика 15%, зрелость 10%, качество данных 5%.
- Известное нарушение грузоподъёмности, бюджета, ширины или A*-проходимости исключает решение. Неизвестное остаётся `unknown` и требует проверки.
- Снимок запуска содержит параметры, ревизию плана и веса.

## Безопасность

Проверены: владелец проекта/файла, path traversal, SSRF локального provider, redirect, upload limit, MIME spoofing, активный SVG, отсутствие внешних ресурсов в PDF-отчёте, CSV formula injection, rate limit, секреты и игнорирование пользовательских данных. Локальный поиск не обнаружил shell/subprocess, `trust_remote_code`, pickle/yaml unsafe load, Docker socket или `dangerouslySetInnerHTML`. `input/`, `.env` и `storage/` подтверждены как ignored.

Абсолютное отсутствие бэкдоров нельзя доказать одним сканированием. Для локальных моделей обязательны: `safetensors`, фиксированный SHA-256, проверенная лицензия/источник, запрет `trust_remote_code`, worker без root и без исходящей сети.

## Ограничения

- Yytsi в текущем adapter принимает только SVG и извлекает стены/двери; масштаб и производственные объекты подтверждаются вручную.
- PDF пока не отображается фоном в canvas.
- Веса Yytsi не включены в git.
- xmarva не подключён: нет явной лицензии, а заявленный контур тяжёл для P0.
- Большинство каталожных габаритов неизвестно, поэтому plan feasibility часто требует паспорта производителя.
- Нет очередей, зарядных событий и многороботной диспетчеризации.

## Рекомендуемая локальная модель зрения

Нужна не одна VLM, а гибрид:

1. vector-first parser для векторного PDF/SVG;
2. изолированная растеризация и классическое CV для сканов;
3. OCR размеров, подписей и легенд;
4. detector/segmentation для стен, дверей, колонн, стеллажей, зон и оборудования;
5. компактная VLM только для семантической сверки;
6. выход всегда `DraftPlan` с `confidence`, `source_region`, `method`, `unresolved` и версиями моделей;
7. перевод пикселей в метры только после подтверждённого масштаба;
8. обязательная ручная проверка до симуляции.

Для ближайшего локального MVP разумно использовать Yytsi как ограниченный SVG-baseline, добавить vector/PDF parser и PaddleOCR, а собственный detector обучать только после появления лицензированного размеченного набора. Полная спецификация находится в `docs/local-vision-model.md`.

## Следующий рабочий промт

Продолжить ветку `feat/plan-recognition-mvp`: добавить изолированную растеризацию PDF с лимитами страниц/пикселей/времени, vector-first извлечение линий и текста, OCR размерных линий, overlay исходника с provenance, golden-set тесты и метрики геометрии. Не добавлять 3D и тяжёлый ML; не считать OCR/VLM источником подтверждённого масштаба без пользовательской проверки.
